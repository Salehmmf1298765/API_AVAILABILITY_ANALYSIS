# مديول أتمتة القوى البيعية الصيدلانية - FTIQ Pharma SFA
## الإصدار 18.0.2.0.0

---

## نظرة عامة

مديول متكامل لإدارة فرق المبيعات الميدانية في قطاع الأدوية، مصمم للعمل بتكامل تام مع مديولات أودو القياسية:

| المديول القياسي | التكامل |
|---|---|
| المبيعات `sale.order` | أوامر البيع الميدانية تصبح أوامر بيع حقيقية |
| المحاسبة `account.move` | الفواتير تُنشأ تلقائياً من أوامر البيع |
| الدفعات `account.payment` | التحصيلات النقدية تسجل كدفعات محاسبية حقيقية |
| المخزون `stock.picking` | أوامر التسليم تُنشأ تلقائياً عند تأكيد البيع |
| المصروفات `hr.expense` | مصروفات المندوبين تتبع النظام المحاسبي القياسي |
| المشاريع `project` | إمكانية ربط المهام بمشاريع |

## دورة الحياة التفصيلية

### 1. تسجيل الحضور الميداني

**النموذج:** `ftiq.field.attendance`

```
المندوب يفتح التطبيق ← يضغط "تسجيل الحضور" ← يُسجل الموقع GPS تلقائياً
├── الحالة: مسجل الحضور (checked_in)
├── يتم تسجيل: خط العرض، خط الطول، الوقت
└── عند الانتهاء: يضغط "تسجيل الانصراف" ← يُحسب عدد الساعات تلقائياً
```

**الحقول الرئيسية:**
- `user_id` - المندوب
- `date` - التاريخ
- `check_in` / `check_out` - وقت الحضور والانصراف
- `check_in_latitude/longitude` - إحداثيات الحضور GPS
- `check_out_latitude/longitude` - إحداثيات الانصراف GPS
- `working_hours` - ساعات العمل (محسوب تلقائياً)
- `visit_count` - عدد الزيارات (محسوب تلقائياً)

**سير العمل:**
```
مسودة → تسجيل حضور → تسجيل انصراف
```

---

### 2. الزيارات الميدانية

**النموذج:** `ftiq.visit`

الزيارة هي النشاط الأساسي للمندوب. يمكن إنشاؤها من:
- الخطة الأسبوعية (زيارة مخططة)
- مباشرة من قائمة "زياراتي" (زيارة غير مخططة)
- من مهمة يومية

```
إنشاء زيارة ← بدء الزيارة (GPS) ← أثناء الزيارة:
│
├── عرض المنتجات الدوائية على الطبيب/الصيدلية
│   └── تسجيل: المنتج، سبب الاتصال، النتيجة، العينات الموزعة
│
├── عرض المواد التسويقية (بروشورات، دراسات)
│   └── تسجيل: المادة، مدة العرض
│
├── إنشاء أمر بيع ميداني → sale.order (تكامل مع المبيعات)
│   └── التأكيد ← فاتورة تلقائية ← أمر تسليم تلقائي
│
├── تسجيل تحصيل نقدي → account.payment (تكامل مع المحاسبة)
│   └── يسوي الفواتير المعلقة تلقائياً
│
├── جرد مخزون أرفف العميل → ftiq.stock.check
│   └── تسجيل المنتجات والكميات على الرف
│
├── التقاط صور (حتى 3 صور)
└── توقيع العميل الإلكتروني

إنهاء الزيارة (GPS) ← تقديم ← اعتماد المشرف
```

**الحالات:**
| الحالة | الوصف |
|---|---|
| مسودة | تم إنشاء الزيارة |
| قيد التنفيذ | المندوب بدأ الزيارة (سُجل GPS البداية) |
| مقدمة | المندوب قدم الزيارة للمراجعة |
| معتمدة | المشرف اعتمد الزيارة |
| مرتجعة | المشرف أعاد الزيارة لاستكمالها |

**الأزرار الذكية في نموذج الزيارة:**
- عداد أوامر البيع المرتبطة
- عداد التحصيلات المرتبطة
- عداد جرد المخزون المرتبط

---

### 3. أوامر البيع الميدانية

**النموذج:** `sale.order` (وراثة من أودو القياسي)

**الحقول المضافة:**
- `is_field_order` - تمييز الأمر كأمر ميداني
- `ftiq_visit_id` - الزيارة المرتبطة
- `ftiq_attendance_id` - سجل الحضور
- `ftiq_latitude/longitude` - إحداثيات GPS
- `ftiq_priority` - الأولوية الميدانية (عادي/عاجل/عاجل جداً)
- `ftiq_delivery_notes` - ملاحظات التسليم

**التكامل التلقائي:**
```
أمر بيع ميداني ← تأكيد الأمر ← يحدث تلقائياً:
├── إنشاء فاتورة عميل (account.move)
└── إنشاء أمر تسليم (stock.picking)
```

هذا التكامل يتم عبر مديول `sale_stock` القياسي في أودو، مما يعني:
- لا حاجة لكود مخصص لإنشاء الفواتير
- لا حاجة لكود مخصص لإنشاء أوامر التسليم
- إدارة المخزون تتم تلقائياً
- التقارير المالية تعكس البيانات الحقيقية

---

### 4. التحصيلات النقدية

**النموذج:** `account.payment` (وراثة من أودو القياسي)

**الحقول المضافة:**
- `is_field_collection` - تمييز الدفعة كتحصيل ميداني
- `ftiq_visit_id` - الزيارة المرتبطة
- `ftiq_attendance_id` - سجل الحضور
- `ftiq_latitude/longitude` - إحداثيات GPS
- `ftiq_check_number` - رقم الشيك
- `ftiq_check_date` - تاريخ الشيك
- `ftiq_bank_name` - اسم البنك
- `ftiq_receipt_image` - صورة الإيصال
- `ftiq_collection_state` - حالة التحصيل (مسودة/محصل/مودع/موثق)

**التكامل التلقائي:**
```
تسجيل تحصيل نقدي ← ترحيل الدفعة ← يحدث تلقائياً:
├── إنشاء قيد محاسبي
├── تسوية الفواتير المعلقة للعميل
└── تحديث رصيد العميل
```

**حالات التحصيل الميداني:**
| الحالة | الوصف |
|---|---|
| مسودة | تم تسجيل التحصيل |
| محصل | تم استلام المبلغ من العميل |
| مودع | تم إيداع المبلغ في البنك |
| موثق | تم التحقق والمطابقة |

---

### 5. مصروفات المندوبين

**النموذج:** `hr.expense` (وراثة من أودو القياسي)

**الحقول المضافة:**
- `is_field_expense` - تمييز المصروف كمصروف ميداني
- `ftiq_attendance_id` - سجل الحضور
- `ftiq_expense_type` - نوع المصروف (نقل/وقود/طعام/إقامة/هاتف/مواقف/أخرى)

**التكامل التلقائي:**
```
تسجيل مصروف ← إنشاء تقرير مصروفات ← اعتماد ← يحدث تلقائياً:
├── إنشاء قيد محاسبي
└── صرف المبلغ للموظف
```

---

### 6. جرد مخزون الأرفف

**النموذج:** `ftiq.stock.check`

نموذج مخصص لرصد منتجات الشركة على أرفف العميل (وليس جرد المستودع).

```
إنشاء جرد ← تسجيل المنتجات والكميات ← تقديم ← مراجعة المشرف
```

**بيانات كل صنف:**
- المنتج والكمية
- تاريخ الصلاحية
- رقم التشغيلة
- موقع الرف
- منتج المنافس وكميته
- صورة الرف

---

### 7. الخطط الأسبوعية

**النموذج:** `ftiq.weekly.plan`

```
المشرف ينشئ خطة أسبوعية ← يحدد العملاء المطلوب زيارتهم ← يعين المندوب
├── كل سطر = عميل + تاريخ مجدول
├── المندوب ينفذ الخطة ← ينشئ زيارات من أسطر الخطة
├── الأسطر المنفذة تتغير حالتها تلقائياً إلى "مكتمل"
├── الأسطر المتأخرة تتغير إلى "فائت"
└── نسبة الالتزام تُحسب تلقائياً
```

**الإحصائيات المحسوبة:**
- عدد الزيارات المخططة
- عدد الزيارات المكتملة
- عدد الزيارات الفائتة
- نسبة الالتزام (%)

---

### 8. المهام اليومية

**النموذج:** `ftiq.daily.task`

```
إنشاء مهمة ← تحديد النوع والعميل والتاريخ ← تنفيذ:
├── نوع "زيارة" ← زر "إنشاء زيارة" → ftiq.visit
├── نوع "أمر بيع" ← زر "إنشاء أمر" → sale.order
├── نوع "تحصيل" ← زر "إنشاء تحصيل" → account.payment
├── نوع "جرد" ← زر "إنشاء جرد" → ftiq.stock.check
└── أنواع أخرى: تسليم، تقرير، متفرقات
```

---

### 9. أهداف المبيعات

**النموذج:** `ftiq.sales.target`

```
تحديد هدف ← نوع الهدف + القيمة المستهدفة + الفترة ← تفعيل:
├── هدف زيارات ← الإنجاز = عدد الزيارات المعتمدة في الفترة
├── هدف مبيعات ← الإنجاز = مجموع أوامر البيع المؤكدة (sale.order)
├── هدف تحصيلات ← الإنجاز = مجموع الدفعات المرحلة (account.payment)
└── هدف عملاء جدد ← الإنجاز = عدد العملاء المسجلين في الفترة
```

**الحسابات التلقائية:**
- `achieved_value` - القيمة المحققة (من البيانات الحقيقية)
- `achievement_rate` - نسبة الإنجاز (%)

---

### 10. إدارة العملاء

**النموذج:** `res.partner` (وراثة)

أنواع العملاء:
- **أطباء** - مع بيانات التخصص والوصف
- **مراكز طبية** - مجمعات عيادات ومستشفيات
- **صيدليات** - نقاط البيع

**البيانات المضافة لكل عميل:**
- التخصص والتخصص الفرعي
- التصنيف (أ/ب/ج/د)
- حالة الواصف
- نوع المسؤول (استشاري/أخصائي/مقيم)
- مستوى المتحدث والقيادة
- نوع مكان العمل
- تصنيف الديون
- رمز اللون
- المنطقة والمدينة
- البيانات الشخصية (الكنية، تاريخ الميلاد، بيانات الأسرة)
- استبيانات مخصصة

**الأزرار الذكية:**
- عدد الزيارات
- عدد أوامر البيع الميدانية
- عدد التحصيلات
- عدد الفواتير
- رابط واتساب مباشر

## هيكل الصلاحيات

| الدور | الصلاحيات |
|---|---|
| **مندوب** `group_ftiq_rep` | إنشاء وتعديل سجلاته فقط، قراءة الإعدادات |
| **مشرف** `group_ftiq_supervisor` | كل صلاحيات المندوب + رؤية فريقه + اعتماد الزيارات والخطط |
| **مدير** `group_ftiq_manager` | كل الصلاحيات + إدارة الإعدادات + حذف السجلات |

**قواعد السجلات:**
- المندوب يرى سجلاته فقط
- المشرف يرى سجلاته + سجلات فريقه (المندوبين المعينين له)
- المدير يرى جميع السجلات
